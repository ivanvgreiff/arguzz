## 0. Scope & non-goals

### 0.1 What D2.G IS
The analysis layer that turns the raw four-variant DBs into the **checkpoint verdict** (Case A–E) by measuring **territory, rejection channels, and accepted-candidate propagation — not raw loc count** (Pro §Phase 4). Its load-bearing, novel deliverable is the **fault-propagation triage filter (Q4)**: classify every accepted proof into `accepted_noop` / `accepted_propagated_candidate` / `accepted_hidden_global_reject` so we definitively know whether we have or have not found soundness bugs. Everything else (territory set-algebra, CGC/local AUC, channel split, the S3/S4/S5 scores, arm occupancy) is largely **reuse/adapt** of the existing `iv_pos_7/analysis` suite.

### 0.2 What D2.G is NOT
- **NOT heavy repair/minimization (Mode-B / D3).** D2.G *identifies* `accepted_propagated_candidate`s; the deep "is this a real soundness bug" adjudication (witness repair/minimization) is **D3** (deferred, New_Master §4). D2.G produces the **D3 design sketch**, not D3 itself.
- **NOT re-running the campaign.** It analyzes the D2.F DBs. (It *does* re-run the small accepted-candidate subset with `--trace` for the triage — §3 — which for the full campaign is a POS rerun pass.)
- **NOT activating L1 / changing scheduling.** The L1 columns are logged (D2.D, inactive); D2.G **re-audits** them (Pro Q3) but does not activate.
- **NOT a paper.** Single-guest checkpoint analysis (Pro D7: multi-guest before any "beats Arguzz" headline).

## 3. The fault-propagation triage filter (Q4 — the centerpiece) — LOCKED

**Goal:** for every accepted proof (`outcome='applied' AND verifier_accepted=1`, equivalently `config_json.soundness_signal=true`), determine definitively whether it is a no-op, a real propagated candidate, or a hidden global reject — so the "soundness_signal count" stops being meaningless raw noise.

### 3.1 Two-tier classification (minimize expensive reruns)
**Tier 1 — cheap DB pass (no rerun), per accept row:**
- `fault_applied` — the row exists with a kind/step/seed (the campaign already injected; corroborated by `--trace` in Tier 2).
- `local_failures = (num_failures > 0)` — should be 0 for an accept (sanity).
- **`global_residue = (global_failures rows for this mutation_id > 0)`.** If an accept has **nonzero `global_failures`** → **`accepted_hidden_global_reject`** (Hook 3's residue flagged it even though the prover accepted — the strongest soundness signal). *This is detectable from the existing DB with NO rerun* (the F13 fix means the campaign already captured Hook-3 residue). **Validate on smoke first** (do the 8 accepts have global_failures? if all 0, all 8 are no-op/propagated, matching the oracle).

**Tier 2 — `--trace` rerun pass (only for accepts NOT already classified hidden-reject):**
Re-run each remaining accept with `--trace --inject --inject-step S --inject-kind K --seed <iter_seed>` (the exact recorded params) + the campaign env, capture the **faulted trace**, and compare to the cached **baseline trace**. **The trace is COARSE — `{step,pc,instruction,assembly}`, no register/memory values, and the only "output" is the `0xDEADBEEF` sentinel (no usable final-state digest — verified).** So **neither full-trace-hash NOR PC-only is a correct propagation detector** (lesson from the B2 follow-up, F21):
- **Full-trace-hash OVER-classifies:** it includes the inject-step `assembly` string, which changes whenever `INSTR_WORD_MOD` touches immediate bits — even for a cosmetic change like a branch *target* on a **not-taken** branch (`beq …,72`→`…,104`, PC sequence unchanged). That is NOT propagation.
- **PC-only UNDER-classifies:** it misses **data-flow** divergences with identical control flow — e.g. a store/load offset change that **crosses a word boundary** (`offset>>2` changes) writes a different memory word, yet PC is identical. **Suppressing all inject-step changes would blind the filter to the most subtle soundness bugs (data corrupted, control flow intact).** (Note F22: a *within-word* offset change like 3939's 4→6 is the opposite — a true no-op, because risc0 word-truncates the address; see rule 3.)
- **LOCKED classification rule (F24 — FAULT-VALUE-aware + kind-aware + width-aware, with a hard fail-safe). ⚠️ The disassembly is BLIND to 10 of the 11 Arguzz kinds:** only `INSTR_WORD_MOD` changes the instruction word; the other 10 (`PRE/POST_EXEC_{PC,MEM,REG}_MOD`, `COMP_OUT_MOD`, `LOAD_VAL_MOD`, `STORE_OUT_MOD`, `BR_NEG_COND`) mutate **values** (`rv32im.rs` audit), leaving the disasm UNCHANGED. So a disasm/trace-only rule would silently no-op every data-only divergence from 10/11 kinds (a `STORE_OUT_MOD`/`COMP_OUT_MOD` that changes a value not reaching control flow → identical disasm + identical trace). The rule therefore keys on the **`<fault>` tag value change `X => Y`** (already parsed as `fault_word_change`), NOT the disassembly:
  - **⚙️ COMMIT DICHOTOMY (F26, source-verified — the physical basis for *which* accepts can be soundness bugs):** the 11 kinds split by **whether the mutation is committed to the proven witness**. (i) **`INSTR_WORD_MOD` is the ONLY *local* kind** — it overwrites the executor's local `word` (`rv32im.rs:662`) but the committed instruction-fetch read (`:643`) returns the original, so the **circuit re-decodes the original instruction** → proof-invisible → it ACCEPTS whenever the mutated execution is absorbed (mostly no-ops; a real bug requires a committed *executor* divergence — cross-word store etc. — that verifies anyway). (ii) **The other 10 kinds COMMIT** their mutation into the executor context — `ctx.set_pc` (`:611,:688`), `ctx.store_memory` (`:624,:701,:1019`), `ctx.store_register` (`:637,:714`), etc. — so the mutated value **enters the witness and is constrained**. ⇒ For a committed kind, an ACCEPT means **the circuit constrained a mutated value and did NOT reject it** = a *direct* soundness candidate (or the value was inert/overwritten before any constraint read it). **Empirical confirmation (D2.F prod batch 1, F26):** of all 1875 accepts, only **2 kinds ever accept** — `INSTR_WORD_MOD` (proof-invisible) and **`POST_EXEC_PC_MOD`** (484 accepts across V6; a *committed* PC write). The other 9 committed kinds → **0 accepts** = the circuit rejects every committed data/reg/mem corruption (soundness working as intended). **`POST_EXEC_PC_MOD` is the only committed kind that accepts — but those accepts are EXPECTED to be dominated by no-ops, NOT candidates (F27 correction).** `random_pc` (`rv32im.rs:167`) overwrites the PC with `original_pc ± {4,8–40,44–4000}`, and the local `pc` is the ORIGINAL instruction address (not the post-execution advance), so the selector-0 `+4` branch on a *sequential* instruction writes back the value the executor already committed → zero divergence → **true no-op**. The circuit has **no PC-provenance constraint** (INV1 §2c, `mem.zir:59-90`) and INV2 found **30/30** accepted `POST_EXEC_PC_MOD` were `pc:N=>N+4` with empty semantic diff; divergent jumps get *rejected*. ⇒ These are classified **`accepted_noop` / evidence=`cf_inert`** (rule 2b below); the soundness lead is only the **divergent residue** (any `POST_EXEC_PC_MOD` accept whose post-inject PC stream actually differs — `strong`), if any survives the full V6 triage. They must still be tier-2 triaged (the trace-rerun confirms +4-noop vs residue), NOT left at the Hybrid-only filter (see §3.2 / B-batch note). It also flags a Hybrid design gap: Hybrid's 4 selected kinds (`arguzz_bridge.py:62`) are `INSTR_WORD_MOD, PRE_EXEC_MEM_MOD, PRE_EXEC_PC_MOD, BR_NEG_COND` — **`POST_EXEC_PC_MOD` is excluded**, so 100% of Hybrid's accepts are proof-invisible `INSTR_WORD_MOD` and Hybrid *structurally cannot* surface the one accepting committed kind (New_Master §4 "revisit if high-value in V6-cTS" rule is now triggered, pending the V6 triage).
  0. **Identity (GUARDED — F24 refinement, D2-opus):** `<fault>` tag shows a **genuine** `X == Y` → `accepted_noop` / **evidence=`identity`**. ⚠️ The identity test is valid ONLY for the kinds whose tag exposes a real original→mutated pair — `INSTR_WORD_MOD` (`word:`), `COMP_OUT_MOD`/`LOAD_VAL_MOD` (`out:`), `STORE_OUT_MOD` (`data:`), `PRE/POST_EXEC_PC_MOD` (`pc:`) — i.e. `info_type ∈ {word,out,data,pc}`. It is **INVALID** for `BR_NEG_COND` (tag `cond:true=>false` → `arguzz_parser.py` yields `info_type='unknown'` with a **spurious `0=>0`**), `*_REG_MOD` (parser **hardcodes** `original_value=0`, so a register-write of 0 looks like `0=>0`) and `*_MEM_MOD` (parser stores the **address** as `original_value`). For those three an `X==Y`-looking tag is meaningless → **fall through to the `weak` fail-safe, NEVER `identity`** (else a `BR_NEG_COND` or a register-write-of-0 would be falsely no-op'd — a new false-noop bug). Implemented as `_fault_is_identity()` keyed on the genuine-pair `info_type` set (verified against `arguzz_parser.py`). **Precedence: Strong (rule 1) is evaluated FIRST in code**, so even a spurious identity that slipped the guard is still caught when control flow diverges. (Identity is the ONLY no-op for a value-mutating kind.)
  1. **Strong:** post-inject PC sequence OR post-inject trace hash (steps > inject) differs → `propagated_candidate` / **evidence=`strong`** (observed downstream divergence).
  - **2b. Control-flow-inert (F27 — `POST_EXEC_PC_MOD` only, CIRCUIT-AUDITED):** if `kind == POST_EXEC_PC_MOD` AND strong did not fire (post-inject pc+trace byte-identical) AND the post-inject window is **non-empty** → `accepted_noop` / **evidence=`cf_inert`**. Justification: `POST_EXEC_PC_MOD`'s only committed effect is the PC (`ctx.set_pc`, `rv32im.rs:688`); the circuit has no PC-provenance constraint (INV1 §2c), so an identical resulting PC sequence ⇒ identical constraints ⇒ provably inert. **GUARD:** the non-empty-window requirement prevents silently no-op'ing a *last-step* `POST_EXEC_PC_MOD` (whose only effect would be the final committed PC, invisible to the step trace) — that falls to `weak`. **SCOPE (pushback on D2-opus's F27):** `BR_NEG_COND` is **deliberately EXCLUDED** and stays at the `weak` fail-safe — it is also PC-only at runtime (`:757`, `rd=0` as any branch), but it flips the branch *condition* (which the circuit *does* verify), and its no-divergence inertness is *reasoned, not audited* like `POST_EXEC_PC_MOD` (INV1 covers `POST_EXEC_PC_MOD`/`INSTR_WORD_MOD`, not `BR_NEG_COND`). `BR_NEG_COND` has **0 accepts** in prod → 0 cost to stay conservative; revisit (audit + add) only if it begins accepting. `PRE_EXEC_PC_MOD` excluded (changes the current fetch, not just the post-inject stream; 0 accepts). The cardinal rule still holds: relax to `noop` ONLY where inertness is *circuit-proven*, never merely "no divergence observed."
  2. **Else (`X != Y`, no control-flow divergence) — branch on KIND (a byte-identical trace means DIFFERENT things per kind):**
     - **`INSTR_WORD_MOD`** (the only disasm-visible kind — the mutation is to the *instruction*, so a byte-identical trace means it executed identically → provable no-op possible). Sub-cases (as below).
     - **Any VALUE-mutating kind** (the other 10): the mutation is to a value (data/register/memory/PC), the disasm is ALWAYS unchanged, and a byte-identical trace means only *no control-flow effect* — **the value still changed → `propagated_candidate` / `weak`** (the coarse trace + sentinel output CANNOT prove a register/memory value change is inert). Most PC/branch mutations diverge control flow → caught `strong` by rule 1; the data-only remainder → `weak`.
  3. **INSTR_WORD_MOD sub-cases (inject-step disassembly changed, PC + post-inject trace identical):**
     - **⚙️ MECHANISTIC BASIS — why INSTR_WORD_MOD is *proof-invisible* (F25, source-verified — this anchors EVERY INSTR_WORD_MOD no-op below).** `INSTR_WORD_MOD` mutates only the **local** `word` variable the executor decodes from (`rv32im.rs:662` `word = new_word`); the **committed** instruction-memory read (`rv32im.rs:643` `word = ctx.load_memory(pc.waddr())`) returns the **original** word and is never written back. The circuit therefore **re-decodes the ORIGINAL instruction** from the committed fetch and constrains *that* (original opcode/imm/regs); the mutated decode lives only in the executor's runtime path. ⇒ An INSTR_WORD_MOD accept is **not** "the circuit accepted a mutated instruction" — it is "the executor's mutated execution still produced a committed witness (memory transactions, register file, PC stream) **consistent with the original-instruction circuit decode**." This is why INSTR_WORD_MOD "always accepts" *whenever the mutation is absorbed*, and why the apparent alignment violation never fires for 3939: the circuit decodes the original `sw …,4` (aligned, `low1=0`, OpSW passes) — **it never sees the mutated `…,6`**. A genuine soundness bug would be an accept where the executor's mutation *did* commit a divergent transaction yet still verified; the sub-cases below decide "absorbed (no-op)" vs "must surface (weak)". *(This also resolves the standing puzzle "every INSTR_WORD_MOD accepts — makes no sense": correct, because the circuit proves the un-mutated program; only a committed executor divergence — cross-word store, taken branch, changed register result reaching a constrained column — can make it reject or, if it doesn't, expose a bug.)*
     - inject-step instr is a **control-transfer (branch/jump)** → `accepted_noop` / **evidence=`cosmetic`** — the mutated field (branch *target*) is **not used** (branch resolved the same; condition/registers unchanged), so it is provably inert. *(Consistent with the basis: circuit decodes the original branch; if the mutated branch had been **taken**, the executor PC would diverge → caught `strong` by rule 1 first.)*
     - inject-step instr is a **store/load** → **the `word_truncated` no-op applies to FULL-WORD ops ONLY (`sw`/`lw`/`lwu`) — F23 width guard (decisive).** risc0 is **word-addressed**: `ByteAddr.waddr() = addr/4` truncates the low 2 bits (`addr.rs:35`), the access targets `waddr` (`rv32im.rs:1019` store / `:906` load), and the misalign trap is **gated off during fault injection** (`rv32im.rs:994`/`:984` store, `:927`/`:917` load, `&& !is_injection_enabled()`).
       - **FULL-WORD (`sw`/`lw`/`lwu`):** `data = rs2` / the whole word is read — the low 2 bits of the address are **ignored**. `word_truncated` no-op requires ALL of: **same mnemonic**, **same base register**, **base provably word-aligned (`b_off % 4 == 0`, see caveat — F25)**, AND **same effective word (`(b_off>>2) == (f_off>>2)`)** → identical word write/read → `accepted_noop` / **evidence=`word_truncated`** (e.g. 3939: `sw`, base `b_off=4` ⇒ `4%4==0` aligned, offsets 4→6 → same word w+1 → TRUE no-op; the circuit decodes the *original* `…,4` per the basis above, and the executor's `…,6` truncates to the same word ⇒ committed transaction matches). A change that crosses a word (`(b_off>>2) != (f_off>>2)`) → `propagated_candidate` / **evidence=`weak`** (executor stores to a different word than the circuit's original-instruction decode expects ⇒ a committed mismatch that *should* reject; if it accepts, that is the soundness bug — surface it).
       - **SUB-WORD (`sb`/`sh`/`lb`/`lbu`/`lh`/`lhu`):** the low 2 bits select the byte/halfword **lane** via `shift = 8*(addr&3)` (`rv32im.rs:973` store / `:907` load). ANY non-identical offset moves the lane (and/or the word) → a **different** byte/halfword written or value loaded → **NEVER `word_truncated`** → `propagated_candidate` / **evidence=`weak`** (the only sub-word no-op is byte-identical disasm, already caught by rule 2). This is exactly the "data corrupted, control-flow intact" class §3.1 must NOT blind itself to — a within-word `sb …,4`→`sb …,6` is a real divergence, not a no-op.
       - **Base-alignment caveat — CONFIRMABLE, do not assume (F23→F25):** the effective word is `(rs1+off)>>2`, **not** `rs1>>2 + off>>2` — an unaligned base register can carry a within-immediate change across a real word boundary, so `(b_off>>2)==(f_off>>2)` is a valid same-word test **only when `rs1` is word-aligned**. The alignment is **cheaply confirmable from the disassembly alone, with no register value:** for a FULL-WORD store/load the baseline run did **not** trap (it's in the baseline trace), so `rs1 + b_off ≡ 0 (mod 4)` ⇒ `rs1 ≡ -b_off (mod 4)` ⇒ **`b_off % 4 == 0` ⟺ `rs1` is word-aligned**. Therefore: gate `word_truncated` on `b_off % 4 == 0`; when `b_off % 4 != 0` (base provably *unaligned*), the `(off>>2)` test is unreliable → **fail safe to `weak`** (an unaligned-base full-word store whose fault offset crosses into a different effective word produces a committed transaction that mismatches the circuit's original-instruction decode — exactly the soundness class we must surface, never bury). ⚠️ **CODE GAP (F25):** `propagation_triage.classify_semantics` (lines ~309-314) currently checks `b_mn==f_mn ∧ FULL_WORD ∧ b_base==f_base ∧ (b_off>>2)==(f_off>>2)` but **omits `b_off % 4 == 0`** — it *assumes* aligned base ("Aligned-base assumption (F23 caveat)" comment) rather than confirming it. This is a spec-vs-code divergence; D2-opus to add `and b_off % 4 == 0` to the condition. (Does not change 3939: `b_off=4`, `4%4==0` passes — no flip-flop.)
     - inject-step instr is **compute** (ALU immediate/operand changed, PC identical) → `propagated_candidate` / **evidence=`weak`** (register result changes; surfaced for D3).
  4. **⛔ FAIL-SAFE (the cardinal rule — F24): any accept that does NOT match a PROVABLE-inert pattern above (`identity`, `cosmetic` not-taken-branch, `word_truncated` full-word-same-aligned-word, or byte-identical-trace INSTR_WORD_MOD) → `propagated_candidate` / `weak`. NEVER silently `noop`.** Over-classifying a real divergence as no-op discards a soundness candidate — the one error we cannot afford (soundness bugs are rare + hidden; a missed one is far worse than an over-surfaced no-op that D3 later discards). When in doubt → `weak`.
- **Sub-ranking for D3 (`constraint_should_fire` column — F24):** value-mutating accepts where a circuit constraint *should* have rejected the mutated value if it reached the constrained column are tagged `constraint_should_fire=True` and ranked above generic data-only `weak`: `COMP_OUT_MOD` (ALU `rd = f(rs1,rs2)`), `LOAD_VAL_MOD` (memory-read), `PRE/POST_EXEC_MEM_MOD` (memory permutation). An ACCEPT for one of these is either (a) the mutated value never reached the constrained column (inert) **or** (b) a constraint is incomplete and accepted a wrong value — **a real soundness bug.** The triage SURFACES them; D3 + a circuit-completeness check adjudicate (a) vs (b). (Implemented as a boolean column in `triage_accepts`; does not change the `class`/`evidence`.)
- **Honest framing (do not overstate):** `weak` = a *surfacing heuristic* (a value/operand changed and we cannot prove from the coarse trace + sentinel output that it is inert) — NOT a verified divergence. Only `identity` (`X==Y`), `cosmetic` (branch target, not taken), `word_truncated` (full-word store/load, same effective aligned word), and byte-identical-trace `INSTR_WORD_MOD` are *provable* no-ops. The principle: classify `noop` **only** when inertness is *proven* (unused field / same word / same value); **everything else → `weak`**. The disasm-only heuristic was twice found too narrow (F22 store-truncation, F23 sub-word, F24 value-mutating kinds) — the root cause is that the coarse trace has no register/memory values, so the `<fault>` tag is the only reliable "something changed" signal, and absent a richer state digest the safe default is to surface.
- **Never use journal/output equality** (sentinel — F19/Pro Q4). **Never reduce to PC-only** (would suppress the `weak` data-instruction tier = the data-corruption-with-intact-control-flow blind spot, F21). Injection itself IS corroborated by the `<fault>` tag on the `--trace` rerun (`word:X => word:Y`) — available for ISS-1 corroboration.
